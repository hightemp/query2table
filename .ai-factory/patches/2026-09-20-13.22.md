# Bound Brave requests and honor search fallback policy

**Date:** 2026-09-20 13:22
**Files:** src-tauri/src/providers/search/{brave,manager}.rs; src/routes/settings/+page.svelte
**Severity:** high

## Problem

An oversized Results per Query value caused Brave to reject requests with HTTP 422. SearchManager then used Serper despite the user selecting Brave, and setting search_fallback_enabled to false had no effect.

## Root Cause

The shared result count was copied directly into each endpoint's count parameter. SearchConfig omitted the persisted fallback flag; the existence of the other API key was the only condition for creating a backup provider. The UI did not expose the flag.

## Solution

Clamp requests inside BraveSearchProvider, so saved settings, explicit-count calls and Research all receive the same protection. Use the public endpoint contracts: web count 1–20 and images count 1–200. An observed validation response allowed 50 for web, but the documented maximum remains 20; do not generalize undocumented server limits or apply the image bound to web search. Each operation still makes one request; no automatic pagination is added.

Include fallback_enabled in SearchConfig, load the persisted flag, and require it both when creating backup clients and before invoking a fallback. Apply the same rules to web/images and both provider directions. Preserve existing default behavior when the setting is absent. Expose the setting in Settings with Save/Discard and explain that it applies to new runs. Keep saved API keys when disabling fallback.

Place Results per Query in the Search section next to the provider selection, retaining the existing setting key and saved values. Research previously overrode it with a fixed count of 8; route that mode through SearchManager.search so it also uses the saved configuration. When exposing a shared setting, check all pipeline consumers for hard-coded overrides.

## Prevention

- Assert outgoing HTTP count parameters at zero, bounds, above bounds, saved-style 100, and u32::MAX for both Brave endpoints.
- Test enabled/disabled fallback with both keys present, both primary providers, both search modes, and primary success/failure. Verify backup call counts and accounting; successful empty primary responses must not trigger fallback.
- Round-trip the visible setting through Save and reopening, and test Discard in both browsers.
