# Ollama reasoning exhausted the answer budget; run errors left the UI running

**Date:** 2026-09-12
**Files:** src-tauri/src/providers/llm/ollama.rs; src-tauri/src/orchestrator/control.rs; pipeline and worker modules; src-tauri/src/commands/run.rs; src/lib/stores/run.ts; RunControls.svelte; src/routes/+page.svelte
**Severity:** high

## Problem

The query about YouTube channels covering robots appeared stuck with Ollama Cloud and deepseek-v4.1-flash. Cancel and Pause did not appear to work.

## Root Cause

The logged runs failed in QueryExpander after successful interpretation, schema planning, and search planning. The provider returned an empty message.content. A live reproduction showed done_reason=length, eval_count=4096, content length 0, and reasoning length 13853; the model spent the entire token budget on reasoning. The same expansion with think=false returned valid JSON in 3.01 seconds (537 generated tokens, 21 queries). The pipeline error propagated to the outer spawned task, which only wrote a file log; database/UI status remained running. Controls were only polled between some pipeline stages, and images/links discarded Pause. Detached worker tasks could outlive cancellation. Frontend start events could arrive before the run ID, and command errors were not displayed.

## Solution

Structured Ollama requests set think=false (GPT-OSS uses low). Provider parsing reports token-limit and empty-answer errors without exposing reasoning content. An independent supervisor polls controls while retaining the current stage future during pause, drops it on cancel, and persists/emits terminal errors. Worker handles own and abort their tasks and honor pause signals. Schema review survives pause without immediately exhausting its idle timeout. Command senders are cloned before awaiting queue space. Frontend buffers startup events and shows pending actions/errors while waiting for backend status acknowledgment.

## Prevention

Test provider responses that contain only thinking or truncated JSON. Exercise Pause/Resume/Cancel during pending HTTP for every pipeline mode, assert bounded cancellation and no duplicate request on resume, and check failure persistence. Test frontend events before the run ID, command failures, and schema edits across pause. Live checks must read credentials from the environment and never record them.

## Verification

The corrected Rust interpretation/schema/search/expansion stages completed the original query with the selected model in 8.4 seconds, producing 4 columns, 13 planned queries, and 39 expansions. This live check did not run the subsequent web-search/fetch/extraction stages. Full automated suite results are recorded in TASKS.md.
