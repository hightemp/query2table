# Preserve legacy settings before inserting defaults

**Date:** 2026-09-12 15:49
**Files:** src-tauri/src/storage/db.rs
**Severity:** medium

## Problem

A saved legacy setting could be lost on startup when its renamed key also had a default value.

## Root Cause

Migration inserted defaults first. UPDATE OR IGNORE then skipped the legacy rename because the destination key already existed, and cleanup deleted the legacy key.

## Solution

Run legacy key renames before default insertion. An existing current key retains precedence; otherwise, the old value becomes the current setting. Missing settings still receive defaults automatically.

## Prevention

Test legacy-only keys, simultaneous legacy/current values, and a second migration after editing a newly added setting. Verify values rather than only checking that keys exist.

## Verification

Regression tests and the complete Rust test suite passed. No production settings database was edited by the diagnostic checks.
