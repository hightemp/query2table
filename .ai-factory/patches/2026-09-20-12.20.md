# Preserve deduplication identity and account at provider attempt boundaries

**Date:** 2026-09-20 12:20
**Files:** src-tauri/src/orchestrator/{pipeline,control,budget_tracker}.rs; src-tauri/src/storage/repository.rs; src-tauri/src/providers/{accounting,llm/*,search/manager}.rs; src/lib/stores/run.ts; src/lib/components/run/CostSummary.svelte
**Severity:** critical

## Problem

Deduplication could overwrite an unrelated first row, leave duplicate records and detach source evidence from the displayed entity. Cost estimates used invented token counts and a universal tariff, missed retries and failed attempts, and could show unknown charges as zero.

## Root Cause

Dedup groups lost their original row positions; persistence then selected the first row of the entire run for every group. Accounting occurred in pipeline stages rather than around actual provider calls. Failure and cancellation paths did not have a shared final accounting step. A cancellation between a committed merge and its UI event could also leave the live table stale.

## Solution

Retain group member indices, map them to saved row IDs, and merge the entire batch in one SQLite transaction. Keep the representative ID, move every source association, and only then remove duplicate rows. Validate run ownership and membership. Reconcile canonical table rows after terminal writes on completion, failure and cancellation. Track the selected row by ID so details refresh when canonical data changes.

Wrap each LLM and search attempt in an accounting guard, preserving response usage even for truncated, empty, malformed and error responses. Prefer reported charges; otherwise retain the selected model-specific rate and estimate from actual usage. Missing cost and explicit zero are separate states. Manual rates are scoped to provider, endpoint and model. Cloud inference requires an official cloud endpoint or explicit official remote-host metadata; model-name suffixes alone do not establish billing origin.

Check the shared ledger before every new request, including retries and fallback. Finalize pending attempts once and seal the ledger against late worker admissions. Queue accounting persistence through ControlWriter; flush after dropping work to avoid reentering the one-connection SQLite pool. Preserve already-produced image/link results when the spending limit prevents further ranking. Research must not buy an additional final answer after reaching the limit.

## Prevention

- Test interleaved groups, singleton rows, unchanged unrelated runs, all source IDs and fetched-page associations, and rollback when a later group is invalid.
- Test reported cost precedence, cache usage, reasoning without double counting, explicit zero, unknown usage, malformed responses, retries, fallback, cancellation and decimal budget boundaries.
- Keep one-connection pause/resume/cancel accounting tests; guard drops and finalization must not count a request twice.
- Test live canonical-row events with an open details dialog and after cancellation, plus stale events from earlier runs.
- Monetary caps are admission checks on known or estimated spending. In-flight and unknown charges can exceed the display; explain this in the UI and retain historical rates with each run.
- Do not repair previously overwritten historical data without recoverable evidence; rerun the affected query.
