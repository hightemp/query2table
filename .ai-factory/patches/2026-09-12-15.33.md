# Configurable reasoning and actionable LLM diagnostics

**Date:** 2026-09-12 15:33
**Files:** providers/llm; orchestrator/control.rs and events.rs; role callers; storage/repository.rs; commands/run.rs; frontend settings, error presenter, issues panel, and history
**Severity:** medium

## Problem

Reasoning behavior was hardcoded, provider output limits often appeared as parsing failures, and swallowed extraction/ranking failures were difficult to discover. Raw errors did not explain what the user could change.

## Root Cause

The request configuration had no effort field, error strings discarded type and usage metadata, and warnings only reached logs. A naive attempt to persist diagnostics inside the supervisor introduced a second failure: it stopped polling work while waiting for a database connection held by that same work.

## Solution

Add a typed reasoning setting and map it per protocol, retaining safe Auto defaults. Classify provider errors before parsing response content; preserve reported usage and retry metadata. Send run-scoped diagnostics through an agnostic provider channel, label calls by role, persist all relevant issues, and render readable causes/actions with optional details. Queue ordered control/status/diagnostic writes and poll a pinned write alongside work, then flush after dropping work on terminal paths. Unknown token counts remain unknown; model content and credentials are not copied into diagnostics.

## Prevention

Exercise all effort values and unsupported model combinations against mock HTTP endpoints. Verify output limit versus context/quota/rate limit classification, HTTP-200 error envelopes, permanent error retry policy, and history visibility after a successful run with skipped rows. Test supervisor persistence while work holds the only SQLx connection, including Pause/Resume/Cancel. Validate frontend settings persistence, explicit error guidance, unknown fallback, issue metadata, and stale-event isolation.

## Verification

242 Rust tests and 65 frontend tests passed; frontend/backend builds and typecheck passed. A live DeepSeek request with reasoning On and max_tokens=64 produced a correctly classified output_limit with one attempt and no retry. See TASKS.md for commands and scope.
