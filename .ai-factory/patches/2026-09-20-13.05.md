# Zero search defaults and provider-specific unknown-cost explanations

**Date:** 2026-09-20 13:05
**Files:** src-tauri/src/storage/db.rs; src-tauri/src/providers/search/manager.rs; src/lib/components/run/CostSummary.svelte; src/routes/settings/+page.svelte
**Severity:** medium

## Problem

The previous empty Brave/Serper price defaults classified successful searches as unpriced. A combined warning did not identify the responsible providers. Saving rates during a run appeared ineffective because that run had already captured its configuration.

## Root Cause

Missing rates intentionally mean unknown, while explicit zero means a zero estimate. Default settings and SearchConfig supplied missing values. CostSummary displayed only the aggregate unknown-attempt count. Persisted run accounting correctly retained the original rates instead of applying later settings retroactively.

## Solution

Default both search providers to zero in persisted settings and runtime configuration. Use SQLite user_version 1 for an atomic, one-time data migration from former empty defaults to zero. Preserve numeric rates and historical stats. After migration, a deliberately cleared price remains unknown across restarts.

Show unknown attempts grouped by provider, link to pricing settings, and explain missing rate/billing data and the fact that settings changes apply to new runs. Continue marking failed attempts without billing responses as unknown, including timeouts; do not silently recalculate history.

## Prevention

Test fresh defaults, upgrades with blank/missing/paid values, repeated migration after deliberate clearing, unchanged history, and successful searches at default zero rates. Verify the warning with mixed search and LLM attempts, including multiple lines for one provider. When diagnosing costs, inspect accounting and setting timestamps without reading API keys, query content or extracted results.
