# План улучшений и исправлений

Аудит версии 0.10.0 (20 октября 2026). Источники: чтение кода, `cargo clippy --all-targets`, `svelte-check`, `npm audit --omit=dev`, `vitest`, а также открытые пункты в TASKS.md, TASKS-RU.md и UI-IMPROVEMENTS.md.

Состояние на момент аудита: 228 фронтенд-тестов проходят, `svelte-check` без ошибок и предупреждений. Clippy выдаёт 37 предупреждений по коду приложения (51 вместе с тестами). `npm audit` находит 3 уязвимых пакета: svelte, dompurify, devalue.

Приоритеты:
- **P0** — ошибка, которая вводит в заблуждение, теряет данные или открывает дыру.
- **P1** — заметная проблема надёжности или удобства.
- **P2** — порядок в коде и полировка.

Пункт считается выполненным, когда код написан и проверен тестом (правило AGENTS.md).

  - `svelte` 5.55.0: XSS через DOM clobbering, ReDoS;
  - `dompurify` ≤ 3.4.15: обходы санитайзера; через него проходят ответы моделей в `Markdown.svelte`;
  - `devalue`: high, приходит транзитивно из `@sveltejs/kit`.

  Сделать: `npm audit fix` или поднять версии вручную, затем прогнать vitest и Playwright.

  Сделано 20.10.2026:
  - `npm audit fix`: svelte 5.57.2, dompurify 3.4.17, @sveltejs/kit 2.70.3, devalue 5.9.4, vite 6.4.4;
  - vitest 3 → 5.0.5: критичная tinypool и @vitest/mocker; нужен Node ≥ 22.12;
  - `npm audit --omit=dev` — 0 уязвимостей;
  - проверено: 228 vitest, 292 Playwright (Chromium и WebKit), `npm run check` чисто, `npm run build`.

  Осталось (low, только dev): `cookie` < 0.7 внутри @sveltejs/kit 2. Ошибка в разборе cookie на сервере SvelteKit, а у нас статическая SPA без сервера, так что приложение не затронуто. Исправление есть только в kit 3, это отдельная миграция (P2).
- [ ] **P0. Не пускать агента и загрузчики во внутреннюю сеть (SSRF).** `HttpFetcher::fetch` (`src-tauri/src/providers/http/client.rs:129`) и `download_image` (`providers/http/images.rs:14`) идут по любому адресу. Адрес выбирает модель, а модель читает чужие страницы, поэтому prompt injection на странице может заставить агента открыть `http://192.168.0.1/…`, `http://localhost:11434/…` или `169.254.169.254`, а потом пересказать ответ или отправить его в поисковый запрос.

  Сделать:
  - разрешать только `http`/`https`;
  - отклонять loopback, private, link-local и CGNAT адреса, причём после DNS-разрешения и на каждом редиректе (свой `redirect::Policy` и resolver);
  - адрес Ollama из настроек — явное исключение.

  Тест: wiremock на 127.0.0.1 отклоняется. Редирект с публичного адреса на приватный тоже отклоняется.
- [ ] **P1. Ограничивать размер ответа во время чтения, а не после.** `response.bytes()` читает всё тело целиком (`client.rs:189`, `images.rs:36`, `providers/llm/endpoint.rs:56`). Ответ без `Content-Length` (chunked) может занять сотни мегабайт памяти, прежде чем сработает лимит. Сделать: читать через `chunk()` с остановкой на лимите, как это уже сделано в `updates/download_verified`.
- [ ] **P1. Сузить CSP** (`src-tauri/tauri.conf.json`).
  - Фронтенд сам в сеть не ходит (`fetch(` в `src/` нет), поэтому `connect-src` с Brave, Serper, OpenRouter и `localhost:*` не нужен. Оставить `'self'` и `ipc:`/`http://ipc.localhost`.
  - `img-src https:` нужен галерее Images и фавиконам; это осознанный компромисс, записать его в AGENTS.md.
- [ ] **P2. Хранить API-ключи в системном хранилище.** Сейчас ключи лежат открытым текстом в таблице `settings` SQLite. Экспорт настроек их уже исключает (`commands/settings.rs:201`), но любой процесс пользователя может их прочитать.
  - Desktop: крейт `keyring` (Secret Service, Keychain, Credential Manager), с миграцией существующих ключей.
  - Android: Android Keystore либо оставить как есть, потому что хранилище приложения и так приватное.
  - Нужен запасной путь для Linux без Secret Service.
- [ ] **P2. User-Agent.** Первый UA ссылается на несуществующий `https://github.com/query2table` (`client.rs:54`); заменить на `https://github.com/hightemp/query2table`. Ещё стоит решить, честно ли менять UA на браузерный, особенно вместе с пунктом 2.1 про robots.txt.

## 2. Ошибки и расхождения поведения с настройками

- [ ] **P0. robots.txt не соблюдается, хотя настройка это обещает.** Настройка `respect_robots_txt` по умолчанию `true` (`storage/db.rs:474`), а `RobotsChecker` (`providers/http/robots.rs`) есть и покрыт тестами. Но ни настройку, ни проверку никто не вызывает. TASKS.md § 22 утверждает, что robots.txt соблюдается.

  Сделать: вызывать `RobotsChecker::is_allowed` в `fetch_pool` и в `fetch` агента ресерча, если настройка включена. Заблокированную страницу помечать в логе и в шагах агента. Вынести переключатель в Settings › Search.
- [ ] **P0. Запуски, прерванные закрытием приложения или сбоем, навсегда остаются Running.** То же записано в UI-IMPROVEMENTS.md § 5 как P0. В `open_database` (`src-tauri/src/lib.rs:47`) есть уборка удалённых запусков и вложений, но статусы `pending/running/paused/schema_review` никто не сбрасывает.

  Сделать: при старте переводить их в `interrupted` (новый статус, бейдж, кнопка «Run again»), а незавершённые ходы ресерча — в `cancelled`. Учёт расходов не трогать. Полноценное продолжение работы — отдельная задача в § 5.
- [ ] **P1. Настройки без эффекта.** `default_export_format`, `enable_semantic_validation`, `evidence_strictness` и `precision_recall` пишутся в базу (`storage/db.rs`), но их не читает ни бэкенд, ни интерфейс.

  Сделать: либо подключить их (для `evidence_strictness` и `precision_recall` план есть в UI-IMPROVEMENTS.md § 8), либо удалить из значений по умолчанию миграцией.
- [ ] **P1. Миграции глушат все ошибки.** Каждый `ALTER TABLE … ADD COLUMN` заканчивается `.ok()` (`storage/db.rs:252`, `:293` и далее). Это скрывает не только «колонка уже есть», но и `database is locked`, нехватку места на диске и ошибки синтаксиса. После такой ошибки приложение стартует со схемой, в которой не хватает колонок.

  Сделать: версионировать схему через `PRAGMA user_version` (или `sqlx::migrate!`), выполнять шаги в транзакции и игнорировать только ошибку `duplicate column`.

  Тест: запуск на базе каждой прошлой версии. Фикстуры есть в `db.rs` tests.
- [ ] **P1. Логи растут без предела.** `tracing_appender::rolling::daily` без `max_log_files` (`utils/logging.rs:28`). Сейчас это 19 файлов, 11 МБ, и объём будет расти. Сделать: `RollingFileAppender::builder().max_log_files(14)`.
- [ ] **P1. Год и другие условия запроса не проверяются** (TASKS.md:54, TASKS-RU.md п. 2). Пример из README про стартапы 2024 года возвращает компании, основанные раньше. Нужно передавать ограничения из `QueryIntent` в extractor и validator и показывать пользователю, как понято условие.
- [ ] **P2. Мёртвая подписка `log-event`.** `+layout.svelte:91` слушает событие, которое бэкенд не отправляет (UI-IMPROVEMENTS.md § 2). Либо транслировать WARN/ERROR из `tracing` вне запусков, либо удалить подписку.
