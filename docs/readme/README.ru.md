**Query2Table** — локальный инструмент для исследований на компьютере (Linux, Windows, macOS) и на Android. Вы описываете, какие данные вам нужны, а приложение само ищет в интернете по разным источникам и на разных языках, загружает страницы, извлекает из них структурированные данные с помощью LLM, убирает дубликаты и показывает результат в таблице, которая пополняется на глазах, — со ссылками на источники для каждой строки. Всё работает на вашем компьютере, без облачного бэкенда.

Кроме таблиц, есть ещё три отдельных режима: **Картинки** — находит изображения и упорядочивает их с помощью LLM по тому, насколько они подходят к запросу; **Ссылки** — читает целиком каждую найденную страницу и возвращает только самые подходящие ссылки с описаниями и оценками релевантности от LLM; **Исследование** — агентный режим, в котором модель сама ищет, читает страницы, рассуждает и пишет ответ в Markdown с источниками.

Приложение есть и для телефонов на **Android**: те же режимы, настройки и история, собранные из того же кода и приспособленные к экрану телефона с нижней панелью вкладок.

Спросите, например: *«Составь сравнительную таблицу векторных баз данных и библиотек поиска с открытым кодом: язык, лицензия, способ развёртывания, назначение и сайт»* — и смотрите, как таблица заполняется в реальном времени.

|-----------|------|

Чтобы перенести настройки с компьютера на телефон, выберите **Настройки → Экспорт настроек…**, отметьте **Включить ключи API и прокси** и импортируйте файл на телефоне. В таком файле лежат ваши ключи: никому его не передавайте и удалите после импорта.

Локальные серверы моделей (Ollama, llama.cpp) можно использовать по сети по их адресу, например `http://192.168.1.10:11434`.

## Возможности

- **Запросы на естественном языке** — опишите, что вам нужно, своими словами
- **Автоматическое определение схемы** — приложение предлагает столбцы таблицы; вы подтверждаете или правите их до запуска
- **Поиск через несколько провайдеров** — Brave Search + Serper с автоматическим переключением на запасной
- **Расширение запроса на разные языки** — поиск ведётся на нескольких языках и по разным странам
- **Извлечение с помощью LLM** — OpenRouter, Anthropic Claude (кэширование промпта, по желанию — чтение PDF целиком), Ollama (локально или Cloud), DeepSeek, Groq, Mistral, Gemini, xAI, OpenAI, LM Studio, llama.cpp или любой OpenAI-совместимый адрес
- **Потоковые результаты** — строки появляются в таблице по мере того, как находятся
- **Извлечение из PDF** — PDF-документы в результатах поиска распознаются автоматически, и из них извлекается текст
- **Режим «Картинки»** — отдельный конвейер, который ищет изображения вместо текста: составляет 6–12 разных вариантов запроса (с помощью LLM или по запасным шаблонам), выполняет поиск картинок через Brave / Serper, затем LLM оценивает каждый результат по строгой шкале релевантности (0.0–1.0); картинки с оценкой ниже 0.7 отбрасываются, остальные сохраняются по убыванию оценки и сразу появляются в интерфейсе; бюджет, отмена и условия остановки (количество / стоимость / время) соблюдаются на всех этапах
- **Режим «Ссылки»** — отдельный конвейер, который вместо таблицы возвращает самые подходящие страницы: составляет варианты поисковых запросов по вашему запросу, выполняет веб-поиск через Brave / Serper (без повторов URL), загружает и разбирает каждую страницу, после чего LLM читает её целиком, оценивает релевантность (0.0–1.0) и пишет краткое описание; страницы ниже порога уверенности отбрасываются, остальные сохраняются по убыванию оценки и сразу появляются в интерфейсе; бюджет, отмена и условия остановки соблюдаются на всех этапах
- **Режим «Исследование»** — агентный режим, который отвечает на открытые вопросы в Markdown вместо таблицы: LLM ведёт цикл вызова инструментов (поиск в интернете, загрузка страницы в виде Markdown, размышление, ответ) не дольше заданного числа шагов, и каждый шаг сразу появляется на ленте хода работы; шаги размышлений (`think`) и сбои (шаги `error`, красным) видны, так что процесс остаётся прозрачным, а итоговый ответ в Markdown с источниками отображается (после очистки) и экспортируется в `.md`; бюджет, отмена и условия остановки соблюдаются на всех этапах
- **Формулы и картинки в ответах исследования** — формулы LaTeX отрисовываются (MathJax, без интернета); агент может искать изображения, рассматривать их и вставлять подходящие в ответ, они сохраняются вместе с прогоном
- **Диаграммы и графики в ответах исследования** — диаграммы Mermaid и графики: столбчатые, линейные, с областями, круговые, точечные, лепестковые и тепловые карты, нарисованные без интернета в теме приложения; сохраняются как SVG или PNG, открываются на весь экран
- **Статистика** — деньги, токены, вызовы моделей, поиски Brave и Serper и объём данных за месяц, год и всё время, с разбивкой по моделям и режимам, самыми дорогими прогонами, местом на диске, экспортом в CSV и месячным бюджетом с предупреждениями
- **Источники для каждой строки** — каждая строка ссылается на страницы, из которых она извлечена
- **Устранение дубликатов** — нечёткое сравнение + уточнение с помощью LLM
- **Настраиваемые условия остановки** — нужное число строк, максимум расходов, максимум времени
- **История прогонов** — просмотр, открытие и повторный экспорт прошлых прогонов
- **Экспорт** — CSV, JSON, XLSX со всеми данными об источниках
- **Тёмная и светлая темы** — переключатель на боковой панели
- **Значок в трее** — уведомления о завершении (на компьютере)
- **Приложение для Android** — то же приложение на телефоне, с раскладкой для маленьких экранов
- **Обновления внутри приложения** — о новых версиях сообщается вместе со списком изменений, а устанавливаются они из приложения после проверки подписи (на компьютере и на Android)
- **Всё локально** — все данные в SQLite, облачный бэкенд не нужен

```bash
# Clone the repository
git clone https://github.com/hightemp/query2table.git
cd query2table

# Install frontend dependencies
npm install

# Run in development mode (starts both Vite dev server and Tauri)
npm run tauri dev

# Build for production
npm run tauri build
```

## Настройка

При первом запуске приложение создаёт локальную базу SQLite с настройками по умолчанию. Откройте **Настройки** на боковой панели, чтобы задать:

| Группа | Настройки |
|--------|-----------|
| **Провайдер LLM** | Провайдер (OpenRouter / Ollama / Ollama Cloud / OpenAI-совместимый), URL, модель, ключ API, режим JSON, температура, максимум токенов |
| **Провайдер поиска** | Провайдер (Brave / Serper), ключ API, запасной провайдер, результатов на запрос |
| **Выполнение** | Параллельные загрузки (по умолчанию 8), параллельные извлечения (по умолчанию 3), тайм-аут загрузки, ограничение частоты запросов, robots.txt |
| **Качество** | Баланс точности и полноты, строгость к подтверждениям, порог уверенности, порог сходства для дубликатов |

Условия остановки (нужное число строк, максимум расходов, максимум времени) задаются для каждого запроса на странице «Запрос».

**Использовать второй провайдер как запасной** управляет автоматическим переключением между Brave и Serper и для веб-поиска, и для поиска картинок. Отключите, чтобы использовать только выбранный основной провайдер, даже если сохранены оба ключа API. Выбор действует для новых прогонов после сохранения; повторные попытки идут через выбранный провайдер. Когда переключение включено, второй провайдер используется только после сбоя, и для него нужен сохранённый ключ.

В **Настройки → Поиск → Результатов на запрос** укажите, сколько результатов запрашивать на каждый поисковый запрос во всех четырёх режимах, включая «Исследование», и сохраните — значение действует для новых прогонов. Для Brave значение ограничивается диапазоном, указанным в документации: [1–20 для веб-поиска](https://api-dashboard.search.brave.com/api-reference/web/search/get) и [до 200 для картинок](https://api-dashboard.search.brave.com/documentation/services/image-search). Это касается и сохранённых ранее слишком больших значений. Большие значения не включают автоматическую загрузку дополнительных страниц выдачи.

### Расходы, цены и лимиты трат

Панель **Расходы** различает суммы, о которых сообщил провайдер, оценки по тарифам моделей, неполные итоги и неизвестную стоимость. Каждое обращение к провайдеру учитывается отдельно, включая повторные попытки, поиски через запасной провайдер, неудачные ответы с данными об использовании и отменённые запросы, итоговую стоимость которых узнать не удалось. Входные и выходные токены берутся из ответов провайдеров; токены размышлений не оплачиваются второй раз сверх выходных.

- **OpenRouter:** в приоритете [стоимость запроса, которую сообщает провайдер](https://openrouter.ai/docs/cookbook/administration/usage-accounting). Если её нет, расход оценивается по сообщённым токенам и публичным тарифам модели, которая на самом деле ответила.
- **Ollama Cloud:** расход кредитов оценивается по [опубликованным тарифам моделей](https://ollama.com/pricing), включая кэшированный вход и известные периоды пиковых цен. Включённые в план кредиты, оплата подписки и реальные списания могут отличаться от этой оценки. Нераспознанные или недоступные тарифы остаются неизвестными.
- **Свои тарифы моделей:** задайте в настройках цену входа и выхода в USD за миллион токенов. Тарифы относятся к конкретному провайдеру, адресу и модели. Явный ноль означает бесплатное использование; отсутствующий тариф никогда не превращается в ноль сам. Опубликованные тарифы загружаются, не меняя сохранённых вручную.
- **Поиск:** для Brave и Serper по умолчанию стоит 0 USD за 1000 запросов, так что поиск в оценки не входит. Укажите реальную цену вашего тарифа, чтобы учитывать его, или оставьте поле пустым, если цена неизвестна. Неудачные попытки без данных о списании остаются без цены. Изменения настроек действуют для новых прогонов; сохранённая история не пересчитывается. При обновлении прежние пустые значения по умолчанию один раз становятся нулём; уже заданные числа и пустые поля, оставленные позже намеренно, сохраняются.

**Максимум расходов** прогона не даёт отправлять новые запросы к провайдерам, когда учтённые траты достигают лимита. Это не гарантированный потолок счёта: оценки могут расходиться с реальными списаниями, неизвестные суммы учесть нельзя, а уже отправленные запросы всё равно могут быть оплачены. Если нужен жёсткий лимит, задайте его на стороне провайдера. Учёт сохраняется при завершении, сбое, отмене и прогонах без результатов. Записи из более старой истории явно помечены как исторические оценки.

При устранении дубликатов сохраняется ID строки первого элемента группы, значения и источники группы объединяются в одной транзакции, а таблица на экране согласуется с историей и экспортом. Перезаписанные ранее результаты в истории автоматически восстановить нельзя; чтобы получить свежие результаты, запустите эти запросы заново.

Кнопки **Сохранить** и **Отменить изменения** в настройках видны при прокрутке. Ссылки на разделы ведут прямо к нужным полям, а при уходе с несохранёнными изменениями предлагается выбор «Сохранить» / «Отменить изменения» / «Остаться». Правки, сделанные во время сохранения, остаются для следующего сохранения.

Результаты показываются в сплошной виртуализированной таблице с локальным поиском и сортировкой с клавиатуры. Откройте **Подробности** строки, чтобы прочитать или скопировать значения целиком и посмотреть сохранённые источники. В исследовании ответ идёт перед раскрывающимся ходом работы. Картинки можно смотреть сеткой или списком и открывать в просмотре с клавиатуры; экспорт и удаление явно показывают ход и итог. Очистка диагностической панели **Логи** не сбрасывает ход работы прогона.

Регрессионные проверки в браузере используют синтетические данные и подменённые команды Tauri: установите тестовые браузеры командой `npx playwright install chromium webkit`, затем запустите `npm run test:ui`. Остальные тесты фронтенда запускаются через `npm test`.

### Ключи API

Нужен хотя бы один ключ API поиска и настроенный провайдер LLM. Для локальной Ollama и OpenAI-совместимых серверов без авторизации ключ API для LLM не нужен:

| Сервис | Где получить ключ |
|--------|-------------------|
| Brave Search | https://brave.com/search/api/ |
| Serper | https://serper.dev/ |
| OpenRouter | https://openrouter.ai/ |
| Ollama (локально) | https://ollama.com/ — ключ не нужен |
| Ollama Cloud | https://ollama.com/settings/keys |
| OpenAI-совместимый | Ключ по желанию, зависит от вашего сервера |

Выберите провайдера в **Настройки → LLM → Провайдер**, заполните его поля и нажмите **Сохранить**. При переключении у каждого провайдера остаются своя модель и свои учётные данные.

Миграции настроек выполняются автоматически при запуске: новые параметры получают значения по умолчанию, а существующие значения сохраняются. Переименованные настройки явно переносятся в бэкенде до вставки значений по умолчанию; изменения формата хранения при выпуске новой версии тоже требуют кода миграции.

Внизу **Настроек** блок **Файлы приложения** показывает фактическую папку данных, базу `data.db` и папку логов. Нажмите **Копировать путь**, чтобы скопировать расположение в буфер обмена, или **Открыть папку**, чтобы открыть его в файловом менеджере. Для базы данных открывается содержащая её папка. Настройки, история, результаты и источники хранятся в `data.db`; диагностические логи — отдельно.

- **OpenRouter:** введите ключ API и выберите модель из [каталога OpenRouter](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) с поиском. Начните вводить, чтобы отфильтровать ID моделей, выберите мышью или стрелками и Enter, а кнопкой **Обновить** загрузите список заново. Каталог можно смотреть и без ключа; для запросов к модели ключ нужен.
- **Ollama (локально):** URL `http://localhost:11434` и название установленной модели.
- **Ollama Cloud:** URL `https://ollama.com`, ключ API Ollama и модель из каталога сервера с поиском. Нажмите на поле модели и начните вводить, чтобы отфильтровать список, затем выберите мышью или стрелками и Enter; **Обновить** загружает каталог заново. Фильтр не меняет выбранную модель, пока вы не выберете результат. Прямой доступ к облаку идёт через [собственный API Ollama](https://docs.ollama.com/cloud). Облако пока не поддерживает [структурированный вывод](https://docs.ollama.com/capabilities/structured-outputs), поэтому JSON запрашивается через промпт и разбирается существующим конвейером.
- **OpenAI-совместимый:** введите базовый URL API вместе с `/v1` и ID модели на сервере. Для [llama.cpp](https://github.com/ggml-org/llama.cpp/tree/master/tools/server) URL по умолчанию — `http://localhost:8080/v1`; укажите имя загруженной модели или заданный псевдоним. Оставьте ключ API пустым, если сервер его не требует. Отключите **Режим JSON**, если сервер не принимает `response_format`.

**Размышления** управляют тем, сколько модель рассуждает перед ответом. **Авто** сохраняет безопасные значения по умолчанию: в структурированных запросах к Ollama размышления отключаются (для GPT-OSS — «Низкий»), у остальных провайдеров остаются их значения по умолчанию. **По умолчанию провайдера** оставляет решение серверу. **Выкл.**, **Вкл.**, **Низкий**, **Средний**, **Высокий** и **Максимальный** запрашивают конкретный режим или уровень; поддержка зависит от модели и провайдера. GPT-OSS в Ollama принимает «Низкий» / «Средний» / «Высокий» и не работает с «Выкл.» и «Максимальный». Изменения действуют для новых прогонов после сохранения.

**Максимум токенов ответа** — лимит на один запрос, который могут делить между собой размышления и сам ответ. Он не связан с лимитами стоимости и времени прогона и с квотой аккаунта у провайдера. Чем больше размышлений, тем меньше токенов может остаться на ответ.

Проблемы с запросами к модели показывают провайдера, модель, этап, запрошенный лимит вывода, сообщённые числа входных, выходных токенов и токенов размышлений и то, запланирована ли повторная попытка. Для лимитов вывода и контекста, квот провайдера, ограничений частоты, ошибок авторизации и сетевых сбоев даются разные объяснения и способы исправления. Проблемы остаются видны, когда отдельные страницы пропускаются, и доступны в истории прогонов. Другие ошибки показывают краткое объяснение, что сделать, и сворачиваемые технические подробности.

**Пауза** приостанавливает обработку на текущем этапе, включая проверку схемы, а **Продолжить** возобновляет её без повторной отправки запроса. Запрос, уже отправленный удалённой модели, может завершиться там и во время паузы. **Отменить** останавливает локальную работу и закрывает ожидающие запросы. Сбои конвейера показываются и сохраняются со статусом `failed`, а исходная ошибка доступна в логе прогона.

## Архитектура

Бэкенд построен как **конечный автомат конвейера** с фиксированными ролями, которые выполняются по очереди:

```
Query → Interpret → Plan Schema → [User Confirms] → Plan Searches
      → Expand Queries → Execute Search → Fetch Pages → Parse Documents
      → Extract Entities → Validate → Deduplicate → [Stop Check] → Done
```

### Роли конвейера

| Роль | LLM | Назначение |
|------|-----|------------|
| QueryInterpreter | Да | Разбирает запрос в структурированное намерение |
| SchemaPlanner | Да | Предлагает столбцы таблицы и их типы |
| SearchPlanner | Да | Составляет поисковые запросы для разных языков и стран |
| QueryExpander | Да | Переводит запросы на нужные языки |
| SearchExecutor | Нет | Вызывает API поиска, собирает URL-кандидаты |
| Fetcher | Нет | Загрузка по HTTP с ограничением частоты и учётом robots.txt |
| DocumentParser | Нет | HTML → чистый текст (без служебных частей страницы) |
| PdfParser | Нет | PDF → чистый текст (через pdf-extract) |
| Extractor | Да | Текст + схема → структурированные строки |
| Validator | Частично | Соответствие схеме + смысловые проверки |
| Deduplicator | Частично | Нечёткое сравнение (strsim) + LLM для спорных случаев |
| LinkRanker | Да | Читает содержимое страницы, оценивает релевантность (0.0–1.0) и пишет описание (режим «Ссылки») |
| ResearchAgent | Да | Ведёт агентный цикл поиск/загрузка/размышление/ответ и пишет ответ в Markdown (режим «Исследование») |
| StoppingController | Нет | Проверяет условия остановки (строки, бюджет, время, насыщение) |

### Конечный автомат

```
Pending → SchemaReview → Running ⇄ Paused → Completed / Failed / Cancelled
```

## База данных

SQLite в режиме WAL со следующими таблицами:

| Таблица | Назначение |
|---------|------------|
| `settings` | Настройки пользователя (ключи API, модели, предпочтения) |
| `runs` | Записи о прогонах со статусом и статистикой |
| `run_schemas` | Подтверждённая схема таблицы для каждого прогона |
| `search_queries` | Составленные поисковые запросы для каждого прогона |
| `search_results` | URL, полученные от API поиска |
| `fetched_pages` | Содержимое загруженных страниц |
| `entity_rows` | Извлечённые структурированные строки (данные в JSON) |
| `row_sources` | Подтверждения для строк (URL, заголовок, фрагмент) |
| `image_results` | Упорядоченные картинки для каждого прогона (режим «Картинки») |
| `link_results` | Упорядоченные подходящие ссылки с описаниями и оценками (режим «Ссылки») |
| `research_steps` | Шаги вызова инструментов агентом для каждого прогона — поиск/загрузка/размышление/ошибка (режим «Исследование») |
| `research_results` | Итоговый ответ в Markdown для каждого прогона (режим «Исследование») |
| `run_logs` | Логи выполнения для каждого прогона |

### Android

Нужны [зависимости Tauri для Android](https://v2.tauri.app/start/prerequisites/#android): Android SDK и NDK (`ANDROID_HOME`, `NDK_HOME`), Java 17 (`JAVA_HOME`) и целевые платформы Rust (`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`). Подключите телефон с включённой отладкой по USB или запустите эмулятор.

```bash
make android-devices    # check the phone or emulator is connected
make android-emulator   # start an emulator (AVD=<name> to pick one)
make android-apk        # build dist/Query2Table_<version>_android.apk
make android-run        # install it on the device and open the app
make android-logs       # follow the app's log
make android-dev        # live reload on the device
```

Сборки подписываются отладочным ключом, если нет файла `src-tauri/gen/android/keystore.properties`. `make android-keystore` создаёт ключ для релизов и этот файл, а также выводит секреты GitHub (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`), которыми процесс выпуска подписывает APK, добавляемый к каждому релизу. Сохраните ключ: обновление встаёт поверх установленного приложения, только если подписано тем же ключом.
